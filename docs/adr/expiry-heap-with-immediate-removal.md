# 주기 청소는 만료 시각 순 min-heap에서 찾고, 지우거나 덮어쓴 key는 heap에서 바로 뺍니다

맥락: 아무도 다시 조회하지 않는 만료된 key를 지우려면, 주기 청소가 만료된 key를 찾을 방법이 필요했습니다. store의 해시 테이블은 rehash 때 버킷 배치를 한 번에 바꾸므로 커서로 훑으면 key를 건너뛸 수 있고, key 대부분에 기간이 없으면 전체를 훑는 비용이 낭비됩니다.

결정: 기간이 있는 key의 entry만 만료 시각 순 min-heap에 넣고, 청소는 맨 앞부터 만료된 것만 꺼냅니다. entry는 만료 시각과 heap 안의 자기 위치를 갖고, key를 지우거나 덮어쓰면 그 항목을 heap에서 바로 뺍니다.

이유: 시간 vs. 공간에서 공간 복잡도를 조금 더 우선시했습니다(Q16). (heap을 고른 이유의 문장을 기다립니다. 문장을 받으면 status를 accepted로 바꿉니다.)

버린 대안: 모든 entry를 커서로 훑기, 무작위 일부 검사, 지운 key의 항목을 heap에 두었다가 꺼낼 때 버리기(같은 key를 기간과 함께 계속 덮어쓰면 heap이 끝없이 커집니다).

결과: 청소 비용은 만료된 key 수를 따라가고, heap의 크기는 기간이 있는 key 수와 같습니다. 대신 기간이 있는 저장, 덮어쓰기, 삭제마다 O(log M)이 더 들고, heap이 항목을 옮길 때마다 entry의 위치를 고쳐야 합니다.
