# 서버는 프로세스 1개, 스레드 1개로 모든 요청을 처리합니다

맥락: 여러 client가 같은 순간에 저장, 조회, 삭제를 요청할 때, 요청을 처리하는 실행 흐름을 몇 개 둘지 정해야 했습니다. 실행 흐름이 둘 이상이면 store를 동시에 부르게 되어, 빌려준 value의 주소(ADR `get-lends-value-until-next-change`)와 해시 테이블의 구조가 깨질 수 있습니다.

결정: 서버는 프로세스 1개, 스레드 1개로 돕니다. 그 스레드가 mongoose 루프 안에서 연결 받기, HTTP 해석, store 호출, 응답 보내기를 모두 맡고, store를 부르지 않는 보조 일도 다른 스레드에 맡기지 않습니다.

이유: (2단계에서 팀원이 말한 문장을 받아 적습니다. 문장을 받으면 status를 accepted로 바꿉니다.)

결과: 동시에 온 요청 때문에 결과가 틀리는 일은 생기지 않습니다. 대신 요청 하나가 오래 걸리면 다른 요청이 기다리므로, M3는 동시성 문제를 지연으로 측정합니다.
