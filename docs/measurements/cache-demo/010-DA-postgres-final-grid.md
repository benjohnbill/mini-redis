# 최종 코드의 PostgreSQL 캐시 성능

최종 커밋 `1a64bd7`에서 상품 API에 같은 요청을 보내 캐시 OFF와 ON을 비교했습니다. 상품 10,000개(시드 1), 연결 32개, 초당 500요청(burst), 준비 10초, 측정 30초입니다. 조회 패턴 6가지에 조회·수정 비율 3가지와 TTL 60초·2초를 조합해 36개 조건을 만들었습니다. 조건마다 캐시 OFF와 ON을 각각 3회 실행했습니다.

## 측정 결과

조회 p50은 요청 절반이 이 시간 안에 끝났다는 뜻입니다. 표에는 각 실행의 조회 p50을 구한 뒤 3회 중앙값을 ms 단위로 적었습니다. 차이는 표에 표시한 값의 ON − OFF이며, 음수면 캐시를 켰을 때 더 빨랐습니다. 적중률과 원본 DB 조회 횟수도 3회 중앙값입니다.

TTL 60초에서 같은 검색을 반복한 `search-repeated`의 p50은 6.56 ms에서 1.92 ms로 줄었고, DB 조회는 15,008회에서 0회가 됐습니다. 캐시 적중률은 100%였습니다. 같은 TTL에서 `detail-uniform`의 p50은 3.73 ms에서 2.44 ms로 줄었고, 매번 검색 조건을 바꾼 `search-varied`는 15.85 ms에서 23.88 ms로 늘었습니다.
