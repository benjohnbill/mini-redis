# 008 rehash 범위를 줄이기 전의 세 시나리오

## 앞 기록과 달라진 점

- **목적:** rehash 범위를 (4, 2, 1)에서 (1, 0.5, 0.25)로 줄이는 변경의 "전" 기록입니다. "후"는 [009](009-CJG-rehash-thresholds-after.md)입니다. 같은 날 같은 머신에서 전후를 나란히 재려고 005와 따로 다시 쟀습니다.
- **시나리오:** rehash와 관계있는 A(방해 없음), C(rehash 경계에서 저장과 삭제 반복), E(버킷을 한 번 늘림)만 쟀습니다.
- **코드:** 005(`6b1ec7d`) 뒤에 `src/`가 바뀐 커밋은 `7d2f5cf` 하나입니다. `src/hash.c`의 세 경계 값을 빌드할 때 `-D`로 바꿀 수 있게 했을 뿐이고, 값은 (4, 2, 1) 그대로입니다.
- **머신:** 005와 같은 머신입니다.

## 결론

목표는 "방해 요청이 있어도 작은 GET의 p99 10 ms 이하"([M3 spec](../../milestones/concurrency/spec.md) Q10)입니다.

| 시나리오 | 작은 GET p99, 3회 (ms) | 판정 |
|---|---|---|
| A 방해 없음 | 1.016, 4.411, 0.702 | 통과 |
| C rehash 경계 | 1.464, 7.194, 0.956 | 통과 |
| E 버킷을 한 번 늘림 | 449.319, 473.853, 481.138 | 초과 (3회 모두) |

- **005와 같은 모양입니다.** E에서 버킷을 늘리는 저장 하나는 542\~571 ms였고, 005의 535\~676 ms 범위 안입니다.
