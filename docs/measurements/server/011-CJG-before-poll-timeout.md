# 011 루프의 대기 시간을 바꾸기 전, 같은 날의 다시 잰 기준

## 앞 기록과 달라진 점

- **목적:** [012](012-CJG-poll-timeout.md)과 같은 날, 같은 조건에서 견줄 개선 전 숫자입니다. 012을 먼저 쟀더니 lab 처리량이 005(초당 약 3만 8천\~4만 9천 개)보다 크게 높게 나왔습니다. 그래서 005와 견주면 머신 상태의 차이가 개선 효과에 섞이므로, 개선 전 코드를 012 바로 뒤에 다시 쟀습니다.
- **코드:** 005(`6b1ec7d`) 뒤로 `src/`를 바꾼 커밋은 `ba4623a`와 그 커밋을 되돌린 `741d157`뿐이므로, `src/`는 005와 같습니다.
- **시나리오:** 루프의 한 바퀴 비용이 드러나는 lab과 A, 주기 청소를 재는 f\~h만 쟀습니다. B\~E는 이 변경과 상관없는 큰 요청과 rehash의 멈춤을 잽니다.
- **머신 상태:** 사용 가능한 메모리는 약 7.4 GiB, load average(1분)는 약 2.2\~2.6이었습니다.

## 결론

- **lab과 A, f\~h 모두 작은 GET의 p99가 목표(10 ms) 안입니다.**
- **회수 지연은 005와 같은 범위입니다.** f가 19\~24 ms, g가 key마다 max 25.9\~28.2 ms, h가 9\~31 ms입니다.
