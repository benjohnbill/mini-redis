# 병합 사슬 #44: 다음 청소나 쉬는 연결 기한까지 잠듦

## 앞 기록과 달라진 점

- **코드:** #35 단계(`66d6de7`)에 PR #44만 병합했습니다. 요청이 없는 루프가 25 ms마다 깨어나지 않고 다음 기한까지 잠듭니다(`src/server.c`). 같은 commit의 깨어남은 [`idle-wakeup/004`](../idle-wakeup/004-CJG-pr44-sleep-until-due.md)에 있습니다.
- **머신과 명령:** 앞 단계와 같습니다. 3회에 약 10분이 걸렸습니다.

## 결론

**요청이 있을 때의 지연과 메모리는 앞 단계와 같습니다.** #44의 이득은 요청이 없을 때 초당 깨어남이 39.8번에서 1.0번으로 준 것이고, 이 기록은 그 변경이 부하 아래의 숫자를 나쁘게 하지 않았다는 확인입니다.

| 지표 | #35 (3회) | #44 (3회) | 판정 |
|---|---|---|---|
| a 작은 GET p99 (ms) | 1.076, 0.540, 0.664 | 1.295, 0.548, 0.572 | 차이 없음 |
| b 작은 GET p99 (ms) | 20.146, 16.310, 15.965 | 16.105, 16.803, 16.862 | 차이 없음 |
| e 버킷을 늘리는 저장 (ms) | 109.655, 71.665, 82.143 | 113.242, 83.524, 90.096 | 차이 없음 |
| g 회수 지연 p50 (ms) | 11.8, 11.6, 11.8 | 11.4, 11.6, 11.9 | 차이 없음 |
| 최대 RSS (모든 시나리오) | | | 1 MiB 안에서 같음 |

- **e 1회째의 p99 20.5 ms**는 #35 단계와 같은 원인입니다. 같은 회의 버킷을 늘리는 저장이 113 ms로 가장 길었습니다.
- **f의 회수 지연(19, 18, 56 ms)은 판정하지 않습니다.** 같은 서버 코드에서 잰 기록들이 2 ms(B1)부터 24 ms(005, 011)까지 흩어져 있어, 이 지표의 흔들림이 PR 하나의 효과보다 큽니다. #44 자신의 기록([012](012-CJG-poll-timeout.md))은 19\~24 ms에서 14\~16 ms로 줄었다고 적었지만, 이 사슬에서는 그 차이를 가를 수 없습니다.
