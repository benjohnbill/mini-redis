# #42 뒤 h의 약 45 ms 멈춤과 glibc mmap 기준값

## 앞 기록과 달라진 점

- **목적:** [#42 사슬 기록](017-CJG-pr42-recv-buffer.md)에서 h(16 MiB value의 만료)에 약 40 ms 멈춤이 새로 생겼습니다. 원인으로 의심한 glibc `malloc`의 동적 mmap 기준값을 가르려고, 기준값을 고정한 실행과 고정하지 않은 실행을 번갈아 쟀습니다.
- **코드:** 사슬의 마지막 단계(`409f6b9`)와 같습니다. 서버 코드는 바꾸지 않았고, 서버 프로세스의 환경 변수만 다릅니다.

## 결론

**기준값을 고정하면 h의 멈춤이 사라집니다.** 고정하지 않은 5회는 모두 작은 GET max가 44.3\~50.2 ms였고, 고정한 5회 중 측정 client가 멈춘 3회째를 빼면 6.6\~17.3 ms였습니다. #42 전의 사슬 값(5.2\~8.0 ms)에 가깝습니다.

- **3회째 고정 실행(55.0 ms)은 판정에서 뺍니다.** 같은 회의 client 늦음 max가 40.0 ms였습니다.
- **원인의 앞부분은 측정으로 확인했고, 뒷부분은 추론입니다.** #42 뒤에는 16 MiB PUT마다 수신 버퍼가 요청 크기로 한 번에 잡히고 연결이 닫힐 때 해제됩니다. glibc는 mmap으로 받은 큰 덩어리가 해제되면 그 크기로 mmap 기준값을 올립니다. 기준값을 고정하면 멈춤이 사라지므로 이 동작이 원인입니다. 기준값이 오른 뒤 어떤 해제가 45 ms를 쓰는지는 프로파일로 보지 않았습니다.
- **고치는 후보:** 서버가 시작할 때 `mallopt(M_MMAP_THRESHOLD, ...)`로 기준값을 고정하면 이 시험의 환경 변수와 같은 효과입니다. 코드는 바꾸지 않았습니다.
