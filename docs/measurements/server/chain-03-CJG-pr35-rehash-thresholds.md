# 병합 사슬 #35: rehash 범위 (4, 2, 1) → (2, 1, 0.5)

## 앞 기록과 달라진 점

- **코드:** #37 단계(`8dd0871`)에 PR #35만 병합했습니다. 버킷당 entry 수의 범위를 (4, 2, 1)에서 (2, 1, 0.5)로 줄여, 같은 key 수에 버킷을 두 배로 둡니다(`src/hash.c`).
- **머신과 명령:** 앞 단계와 같습니다. 3회에 약 10분이 걸렸습니다.

## 결론

**서버 지연에서는 치른 값만 보이고, 얻은 것은 서버 측정의 해상도 아래에 있습니다.** #35가 노린 조회 시간 감소는 같은 commit을 서버 없이 다시 잰 [`rehash-micro/chain-01`](../rehash-micro/chain-01-CJG-pr35-on-main.md)에서 key 100,000\~4,194,304개일 때 16.5\~22.3%(119\~408 ns)였지만, 서버 전체의 작은 GET p50은 3회 범위 안에서 같습니다. 반면 메모리와 버킷을 늘리는 멈춤은 #37 위에서 분명히 늘었습니다.

| 지표 | #37 (3회) | #35 (3회) | 판정 |
|---|---|---|---|
| c 최대 RSS (MiB) | 805.4, 805.4, 805.4 | 837.4, 837.4, 837.4 | +32 MiB (+4.0%) |
| e 최대 RSS (MiB) | 869.4, 869.4, 869.4 | 965.4, 965.4, 965.4 | +96 MiB (+11%) |
| e 버킷을 늘리는 저장 (ms) | 56.020, 29.879, 29.383 | 109.655, 71.665, 82.143 | 약 2배로 증가 |
| e 작은 GET p99 (ms) | 1.127, 1.128, 0.676 | 15.722, 1.016, 1.800 | 1회째 목표 초과 |
| c 작은 GET p50 (ms) | 0.079, 0.083, 0.080 | 0.079, 0.083, 0.079 | 차이 없음 |
| c 작은 GET p99 (ms) | 0.710, 0.600, 0.716 | 0.668, 0.496, 0.595 | 차이 없음 |

- **메모리 증가는 버킷 배열의 크기와 정확히 맞습니다.** `struct list`는 32바이트입니다. c는 key 2²²개에 버킷이 2²⁰개(32 MiB)에서 2²¹개(64 MiB)로 늘어 +32 MiB입니다. e는 늘리는 순간 옛 배열과 새 배열이 함께 있어 32 + 64 = 96 MiB에서 64 + 128 = 192 MiB로 늘어 +96 MiB입니다. 두 계산값이 잰 차이와 같습니다.
- **멈춤이 두 배가 된 이유도 같은 배열입니다.** #37 뒤에 남은 멈춤은 새 배열을 할당하고 버킷마다 `list_init`하는 시간입니다. #35는 그 배열을 64 MiB에서 128 MiB로 키우므로 멈춤도 약 30 ms에서 72\~110 ms로 늘었습니다. #35의 [`rehash-thresholds.md`](../../milestones/perf/ideas/rehash-thresholds.md)가 "새 배열이 128 MiB(약 72 ms)"라고 예상한 값과 맞습니다.
- **e 1회째의 p99 15.7 ms는 이 멈춤 때문입니다.** 같은 회의 버킷을 늘리는 저장이 110 ms로 가장 길었고, client 늦음은 max 4.8 ms로 작았습니다.
- **조회 이득이 서버 지연에 보이지 않는 이유는 크기와 출력 단위입니다.** 400만 key에서 줄어드는 0.4 µs는 작은 GET 하나(약 80 µs)의 0.5%로, 3회 사이의 p50 흔들림(약 5%)보다 작습니다. 또 `bench.py`는 지연을 1 µs 단위로 출력하므로 0.4 µs 차이는 처음부터 보일 수 없습니다. 이득이 보일 수 있는 곳은 서버가 CPU를 다 쓰는 최대 처리량이며, 요청 하나의 CPU 시간(초당 약 7만 요청이면 약 14 µs)으로 계산하면 약 3%입니다. 이 값은 재지 않았습니다.
- **f 1회째의 회수 지연 53 ms가 #37 단계(51 ms)에 이어 다시 나왔습니다.** B1에서는 3회 모두 2\~4 ms였습니다. 두 단계 모두 1회째에만 나왔고 나머지 회는 3\~5 ms입니다. 005에서 같은 시나리오가 4\~24 ms였으므로 아직 흔들림의 범위로 보지만, #37 뒤에만 나타나므로 다음 단계에서도 지켜봅니다.
