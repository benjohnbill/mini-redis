# 02: python 열린 루프로 방해 요청 중 작은 GET의 지연을 잰다

**Status:** ready-for-agent

**What to build:** 측정하는 팀원이 `make bench`로, 방해 요청이 도는 동안 작은 GET의 지연을 요청 종류별로 봅니다. 작은 GET은 정해진 시각마다 보내고(열린 루프), 지연은 "보냈어야 할 시각"부터 잽니다. 그래야 서버가 멈춘 동안 쌓인 기다림이 숫자에서 빠지지 않습니다. 결과는 spec에 남겨 06이 목표와 대조합니다. 결정은 `../spec.md`의 Q2, Q3, Q9, Q10을 따릅니다.

**Blocked by:** 01

완료 조건:

- [ ] python3 표준 라이브러리만 쓴다
- [ ] 작은 GET을 일정한 간격으로 보내고, 지연을 응답 시각에서 예정 시각을 뺀 값으로 잰다
- [ ] 동시 연결 100개 규모(Q2)로 보낸다
- [ ] 시나리오 A, 방해 없음: python으로 잰 기준선이 01의 wrk 기준선과 크게 다르지 않은지 확인한다. 크게 다르면 python client가 병목이라는 뜻이므로 `## Comments`에 적는다
- [ ] 시나리오 B: 16 MiB value 저장을 반복하는 중
- [ ] 시나리오 C: 01의 미리 채우기로 4,194,304개를 넣은 뒤, 그 경계에서 새 key 저장과 삭제를 번갈아 보내는 중
- [ ] 시나리오 D: 16 MiB value 삭제를 반복하는 중
- [ ] 시나리오마다 작은 GET의 p50, p99, max와 방해 요청 자신의 지연을 따로 출력한다
- [ ] `make bench`가 01의 실험실과 함께 이 시나리오들을 실행한다. 하나만 돌릴 때는 스크립트를 직접 실행한다
- [ ] 결과와 환경(머신, 빌드, 명령)을 `../spec.md`의 "측정 결과" 절에 적는다
- [ ] `make verify`가 통과한다
