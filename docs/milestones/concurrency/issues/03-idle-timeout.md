# 03: 10초 동안 바이트가 오가지 않는 연결을 닫는다

**Status:** ready-for-agent

**What to build:** 요청을 끝까지 보내지 않고 멈춘 client는 10초 뒤 `408`과 `request_timeout`을 받고 연결이 닫힙니다. 응답을 받은 뒤 쉬는 연결은 10초 뒤 응답 없이 닫힙니다. 기한은 받기와 보내기 모두에서 마지막으로 바이트가 오간 때부터 세므로, 느린 네트워크로 큰 body를 보내거나 큰 응답을 받아 가는 정상 client는 끊기지 않습니다. `408` 응답은 api 층이 만들고(M2의 `411`, `413`과 같음), 검사는 같은 mongoose 루프 안에서 합니다. 스레드를 더하지 않습니다(ADR `single-thread-event-loop`). 결정은 `../spec.md`의 Q4, 응답 표, Testing Decisions의 "10초 기다림"을 따릅니다.

**Blocked by:** None (can start immediately)

테스트 시나리오(팀 확인 전). 테스트 이름은 아래 문장을 그대로 씁니다.

- [ ] 요청 시간 초과 응답은 408과 {"error":"request_timeout"}이고 Content-Type은 application/json이다
- [ ] [T12] (기능) 헤더를 보내다 10초 동안 멈춘 연결은 408과 request_timeout을 받고 닫힌다
- [ ] (기능) body를 보내다 10초 동안 멈춘 연결은 408과 request_timeout을 받고 닫힌다
- [ ] (기능) 응답을 받은 뒤 10초 동안 쉬는 연결은 응답 없이 닫힌다
- [ ] (기능) body를 10초보다 오래 걸려 꾸준히 보내는 연결은 끊기지 않고 저장된다
- [ ] (기능) 16 MiB 응답을 10초보다 오래 걸려 천천히 받아 가는 연결은 끊기지 않는다

그 밖의 완료 조건:

- [ ] 서버의 기한은 10초로 고정하고, 테스트를 위한 인자나 테스트용 빌드를 만들지 않는다
- [ ] 기다리는 기능 테스트들을 같은 시간 안에서 함께 돌려, `make verify`가 늘어나는 시간이 약 15초를 넘지 않게 한다
- [ ] 천천히 받아 가는 테스트는 커널의 소켓 버퍼가 응답을 다 받아 두지 못하도록, 서버가 보내는 속도보다 느리게 읽는다
- [ ] M1·M2의 기존 테스트가 그대로 통과하고, `make verify`가 통과한다
