# 06: 측정 결과를 목표(p99 10 ms)와 대조한다

**Status:** ready-for-agent

**What to build:** 02의 측정 결과를 목표 "방해 요청이 있어도 작은 GET의 p99는 10 ms 이하"와 대조해, 시나리오마다 통과인지 초과인지 spec에 남깁니다. 초과 항목이 있으면 AI는 고치지 않고 원인 후보와 줄이는 방법의 후보만 보고한 뒤 멈춥니다. 무엇을 어떻게 줄일지는 드라이버(사람)가 판단하고(Q14), 그 원리를 PR에 적습니다. 결정은 `../spec.md`의 Q10, Q13, Q14를 따릅니다.

**Blocked by:** 02

완료 조건:

- [ ] `../spec.md`의 "측정 결과" 절에 시나리오별 판정 표(작은 GET의 p99, 목표, 통과 또는 초과)를 적는다
- [ ] 초과 항목마다 원인 후보와 줄이는 방법의 후보를 이 파일의 `## Comments`에 적고 멈춘다
- [ ] rehash가 초과하면 Q13의 후보(나눠 옮기기, 줄이는 기준 늦추기, 버킷을 처음부터 크게 잡기, 한계로 기록하기)를 비교해 적는다. `hash.c`를 고쳐야 하는 후보를 고르면, L2의 코치 합의 때문에 코치의 확인을 먼저 받는다
- [ ] 드라이버의 결정을 `../spec.md`에 "(5단계에서 결정, 날짜)"로 적는다
- [ ] 고치기로 한 항목은 고친 뒤 02의 측정을 다시 돌려 목표 안인지 확인한다. 고치는 일이 크면 08번부터 새 티켓으로 나눈다
- [ ] 고치지 않기로 한 항목은 07이 README의 "알려진 한계"에 적도록 `## Comments`에 남긴다
- [ ] `make verify`가 통과한다
