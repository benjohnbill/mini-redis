# 04: 주기 청소가 조회되지 않는 만료된 key를 지운다

**Status:** ready-for-agent

**What to build:** 아무도 다시 조회하지 않는 만료된 key도 메모리에서 지워집니다. store는 기간이 있는 key만 만료 시각 순 min-heap에 넣고, key를 지우거나 덮어쓰면 heap에서 바로 뺍니다(ADR `expiry-heap-with-immediate-removal`). 서버는 `main`의 루프에서 `mg_mgr_poll`이 돌아온 뒤, 기한에서 S ms가 지났으면 주기 청소를 부르고 다음 기한을 "기한 + S"로 잡습니다(Q17). 청소 한 번은 heap의 맨 앞부터 만료된 key를 최대 K개 지웁니다(Q18). S, K, `POLL_INTERVAL_MS`는 빌드할 때 정하는 상수이고(Q19), 측정 전에는 드라이버가 정한 임시 기본값을 씁니다. 결정은 `../spec.md`를 따릅니다.

**Blocked by:** 02

테스트 시나리오(팀 확인 전). 테스트 이름은 아래 문장을 그대로 씁니다.

- [ ] 주기 청소는 만료된 key를 지우고 지운 개수를 돌려준다
- [ ] 주기 청소는 한 번에 K개보다 많이 지우지 않고, 남은 key는 다음 청소가 지운다
- [ ] 주기 청소는 만료 시각이 이른 key부터 지운다
- [ ] 주기 청소는 만료 전인 key와 기간이 없는 key를 지우지 않는다
- [ ] [T17] 기간과 함께 저장한 key를 기간 없이 덮어쓰면 주기 청소가 그 key를 지우지 않는다
- [ ] 기간과 함께 저장한 key를 지우면 주기 청소가 지운 개수에 넣지 않는다
- [ ] 같은 key를 기간과 함께 여러 번 덮어써도 주기 청소는 마지막 기간만 본다
- [ ] 만료된 key가 없으면 주기 청소는 아무것도 지우지 않는다
- [ ] 기간이 있는 key를 많이 넣고 무작위로 지우고 덮어써도 남은 key를 모두 조회하고 만료 순서대로 청소된다

그 밖의 완료 조건:

- [ ] 주기 청소는 handler 밖에서만 돌고, 스레드를 더하지 않는다(ADR `single-thread-event-loop`)
- [ ] heap의 메모리가 부족하면 저장이 실패하고 store는 바뀌지 않는다(M2의 `500 out_of_memory`와 같은 길)
- [ ] `store_destroy`가 heap도 해제하고, ASan이 누수를 보고하지 않는다
- [ ] `make verify`가 통과한다
